## 2. 保留原始层，分开证据层与检索层

建议沿用现有架构的 Source span / Evidence group / Retrieval unit 模型：

```text
原 PDF + 冻结的 MinerU JSON、HTML、图片
                 ↓
     block 清点、分类、异常报告
                 ↓
 原文片段 + 审核后的结构/关系 + 质量标记
                 ↓
      条款/表格行/附注级检索单元
                 ↓
   命中条款 → 补齐限定附注/例外/冲突 → 回答
```

- 原始层不改动，记录 PDF 与 JSON 文件哈希。
- 证据层保存原文、来源 block、页码、原始 bbox、表格定位信息。中英文各自保留来源。
- 检索层允许去格式、分词、简繁别名、保险术语别名；这些处理结果不能冒充原文引句。
- 同主题中英文和摘要表格通过 evidence group 关联；关联表示同主题，不自动表示内容完全等价。

建议 Source span 的最小字段：`span_id`、`source_sha256`、`raw_json_sha256`、`raw_block_indices`、`raw_text`/`raw_html`、`pdf_page`、`raw_bbox`、`language`、`section_path`、`kind`、`quality_flags`、`review_status`。表格增加原始行/列定位；混合语言单元格可保留共同的表格来源及各自字符范围。

稳定 ID 可由“固定 JSON 哈希 + 数组索引 + 子片段定位”产生。重新解析后应形成新来源版本，不能让旧审核记录静默套用到新 block。

## 3. 清洗规则

### 3.1 先识别语义，再做字符规范化

自动化可以处理：UTF-8 读取、HTML 实体解码、确定性的展示格式转换、无意义空白、Markdown 对货币符号的转义，以及明确的重复装饰元素。

必须先保留并解析 `<sup>`、`<sub>`、LaTeX、星号等语义标记，再做规范化。不要先全局 NFKC 或删除特殊字符：这会把脚注上标与金额、年数混在一起。未识别的数学表达式保留原格式并标记待检查。

数字、货币、百分号、比较符号、否定词、“只适用”“至少”“每次”“合计”“以较低者为准”都属于事实内容。中文空格只在明确的断行位置合并；英文断词和拼写问题不能用无条件正则修复。

对 U+001A 等异常：原文层留存原始字符，界面可用明确的“解析缺字”提示展示；先标记受损 span，必要时使用另一个已核对的完整证据，不能把残缺句子当作完整原文。当前 `curation.json` 约定不允许供应或改写源文本，因此本方案不把纠字偷偷塞进 curation。若后续需要精确修订引句，应另行设计可审计的 PDF 转录/勘误层，并调整该约定，记录原字符、修订字符、视觉依据、审核者及修订版本。

### 3.2 布局类型不是删除依据

- `page_number` 一般不入检索，但先判断是否误识别了章节号。
- `header` 里的“財富增值優勢”“提存彈性”可成为章节路径；去掉重复索引文本之前，先保留标题作用。
- `footer`/`page_footnote` 按内容判断，保留产品限制、说明日期和必要免责声明。
- 图片分为装饰照片、二维码、条款图示、计算图。装饰可不入索引，条款图示必须审查是否包含正文未覆盖的信息。
- 多栏页依据 bbox 和版面容器组织阅读顺序，不能全页按 y 坐标排序，否则会把左右两栏逐行交错。

第一版可以用少量明确的逐页布局规则，不必为这一份 20 页 PDF 建通用版面引擎。

### 3.3 附注作为必需证据建立链接

编号使用带作用域的标识，例如 `document:note:6:zh-Hant`、`page-8:symbol-star:en`。末页公司介绍的 `*` 与第 8 页利率的 `*` 不是同一附注。

正文中的引用标记保留为 `note_refs`，用已审核的链接解析到具体 source spans。机器可提出候选，跨页关系通过原页和内容核对。附注自身也可检索。

例如：

```text
“定期提款”正文（PDF 第 10 页）
  ├─ requires 附注 6（第 12 页）：10 年门槛、金额、期限、费用
  └─ requires 风险提示（第 10 页）：继续扣费、价值不足可能失效
```

类似地，“保證可保權益”需要附注 3；收费条目需要附注 10；假设利率需要第 8 页的非保证与日期说明。第 16 页摘要表里的同一权益也要连接这些条件，不能只给正文加链接。

检索后的扩展由程序执行，不依赖模型碰巧找到附注。上下文超预算时丢弃较低优先级的整个证据组，不能留下权益但删掉它的限制条件。

### 3.4 表格按条件完整的行构建检索文本

解析 HTML 并展开 rowspan/colspan；每个检索单元继承表名、行标题、列标题和适用条件。保存原 HTML 与对应图片，HTML 是结构输入，存在粘连时必须回看原页，不能视为无误事实。

例如第 17 页最低保障额的检索单元必须同时带上：计划类别 `FP80/100/130`、年龄 `<45`、签发地区 `香港`、货币及金额。不要孤立索引 `30,000`。

复杂子表需要人工声明“哪个原始字符串区间对应哪个逻辑行”的结构映射，不能从粘连的 `15/20/2530` 猜出年份。第 16 页额外回报可与第 9 页清晰列出的对应条款交叉核对。

省略号不是缺失数值，不进行插值。保单示例中的 `$` 若没有明确货币说明，不能自动当作美元。表格跨页时只在栏目一致且原页确认后续接，并保留每个片段各自的页码。

### 3.5 双语分别保存，简体作为检索别名

- 原始繁体中文与英文均保留，不把英文统一翻译成中文再存库。
- 混合段落/表格单元格先按句子和布局分段；不能只按“遇见英文字母就切开”，产品名、币种和缩写常嵌在中文句子里。
- 简体转换和双语术语表只扩大检索覆盖，引用仍显示原语言原文。
- 金额、比例、年龄、期限、适用对象的对齐检查产生冲突候选，确认原页后才升级成 `reviewed_conflict`。
- 第 17 页的已核实冲突必须跟随查询返回，即使用户只用一种语言提问，也不能只给那一种语言的金额。

## 4. 切块与来源呈现

先按条款、完整附注、表格逻辑行和风险说明切块，再对过长条款分成子片段。子片段保留父条款关系；重要条件不依赖固定 overlap 恰好覆盖。

起步不需要语义重写或大量合成问答。标题、术语、适用条件和原文构成检索文本。长度上限只是辅助参数，由实际问答验证调整，不是主要分块依据。

引用统一显示 PDF 物理页 `page_idx + 1` 并能打开原 PDF。印刷页码只作可选提示，保留 `raw_page_number_label` 与 `verified_printed_page` 的区别。原始 bbox 看起来采用约 0–1000 的坐标范围，不能直接当作 PDF points；第一版提供页级链接和摘录即可。

## 5. 适合三天任务的实现顺序

1. **扫描与异常清单**：稳定 block ID、来源哈希、页码和类型统计、控制字符/空块/粘连候选；确定正文、风险披露、九张表和附注的覆盖范围。
2. **小型审核记录**：完成 1–10 号双语附注及局部符号附注链接；核对九张表的结构、数值和条件；记录原文冲突、受损文本、印刷页码异常。审核字段区分机器核对与人工复核，不虚报人工审核。
3. **确定性生成 corpus**：导入、结构恢复、检索规范化、关系验证依次执行。输出 `data/corpus.json` 和清洗报告；运行时只加载产物。
4. **检索验收**：先使用现有架构建议的简单检索，重点检查“找到了主条款后，条件是否完整”。确认语料正确后，再衡量是否需要多语向量检索。

推荐辅助产物为 `data/curation.json`（只存关系、结构定位、审核状态）、`data/cleaning-report.json`（异常、排除原因、未解决项）和一份三语言小型评测集。具体字段属于待实现设计。

LLM 可辅助分类、找候选链接或异常，但不能静默补数字、补否定词、决定中英文谁正确，或把改写当作原文证据。

## 6. 验收标准

- 所有 380 个原始块都有去向：保留、元数据、装饰排除或待复核，并记录理由；不要求所有块都进索引。
- 每个可引用 span 都能追到固定来源版本、block/表格位置、1–20 的物理页。
- 10 对编号附注完整保留，作用域内引用全部可解析；局部符号脚注另行核对。
- 九张表均有逐表审核状态；数值、币种、比较符和对应条件未被拆散，存在粘连的表不能自动判定为审核通过。
- 四个 U+001A 的处理均有记录；受损引句不得伪装成无损原文。不能只检查 U+FFFD 为零。
- 重跑生成过程产物一致；生成文本、简体别名和改写不能取得原文引用资格。
- 问“4% 是否保证”时带出非保证和日期说明；问“2.5% 保证”时保留满 15 年及账户价值比较条件。
- 问“每月最低提款”时同时有金额、保单满 10 年及至少一年提款期；问“暂停交费”时带出继续扣费和保单失效条件。
- 问“最低增加保障额”时展示已核实的中英文金额差异，不自行修正。
- 同一组核心问题分别用英文、简体和繁体提问，检查相关证据、必需附注和引用页码；答案措辞可不同，不能遗漏关键条件。
